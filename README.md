# Requirements Analysis

**ID:** RA-PRODUCT-BFE-DRIVE
**Статус:** ""

## Видение системы — VISION-BFE-DRIVE

Облачное файловое хранилище по принципу OneDrive, в котором пользователи могут хранить файлы и папки, управлять файловой структурой, получать назначенный им доступ к отдельным папкам других пользователей и в дальнейшем работать с хранилищем через Web, Desktop и Android-клиенты.

## Цель проекта — GOAL-BACKEND-V1

Создать законченное серверное ядро облачного файлового хранилища и стабильный API-контракт, достаточный для последующего независимого подключения Web, Desktop и Android-клиентов. Сервер должен обеспечивать аутентификацию пользователей, файловое дерево, хранение содержимого файлов в Yandex Object Storage, управление доступом к папкам, журнал изменений и протокол инкрементальной синхронизации, а также обнаружение конфликтующих изменений по версии файла. Клиентские приложения в данный проект не входят.

# Границы Backend V1 — SCOPE-BACKEND-V1

## Входит в Backend V1

### SCOPE-ADMINISTRATION

Администратор системы имеет доступ ко всем файлам и папкам всех пользователей независимо от их владельца и назначенных прав доступа. Администратор может выполнять над любыми файлами и папками все файловые операции, предусмотренные для аутентифицированного пользователя, включая просмотр структуры и содержимого, получение исходного файла, создание папок, загрузку файлов, изменение содержимого, переименование, перемещение и удаление. Ограничения ACL и скрытия родительской структуры не ограничивают эти административные полномочия; администратор также может управлять доступом к любым папкам и создавать учётные записи пользователей.

### SCOPE-AUTH

Создание учётных записей пользователей администратором, аутентификация пользователей, поддержание пользовательской сессии и получение данных текущего пользователя. Самостоятельная регистрация пользователей в Backend V1 не поддерживается.

### SCOPE-INITIAL-ADMIN

При первоначальном развёртывании или инициализации системы должна быть создана первоначальная административная учётная запись без участия уже существующего администратора и вне обычного процесса создания пользовательских учётных записей. Конкретный технический механизм создания этой учётной записи на данном уровне не определяется.

### SCOPE-FILE-TREE

Управление иерархическим файловым деревом: создание папок, просмотр содержимого доступной папки, переименование, перемещение и удаление файлов и папок, а также получение метаданных файлов.

### SCOPE-FILE-CONTENT

Загрузка новых файлов, скачивание исходного содержимого файлов при наличии разрешения на такую операцию и изменение содержимого существующих файлов при наличии соответствующего разрешения, включая загрузку больших файлов с возможностью продолжения незавершённой передачи.

### SCOPE-CONTROLLED-VIEW

Если пользователю разрешён просмотр файла, но запрещено получение исходного файла, система должна предоставлять для просмотра отдельное представление содержимого, не выдавая пользователю исходный файл или его исходные байты.

### SCOPE-FILE-AUDIT

Система должна фиксировать действия пользователей с файлами, позволяя определить, кто загрузил файл, кто успешно получил его содержимое или представление для просмотра, кто скачал исходный файл и кто изменял содержимое файла. Для зафиксированного действия должны быть известны как минимум файл, пользователь, вид действия и время его совершения. Успешная выдача пользователю содержимого или представления файла считается просмотром. Успешное скачивание исходного файла также считается просмотром с точки зрения определения факта ознакомления пользователя с файлом. Изменение содержимого файла само по себе не считается просмотром. Система должна позволять определить среди пользователей, которым в текущий момент доступен файл, пользователей, которые ещё не просматривали и не скачивали его. Подробная информация об активности пользователей в отношении файла доступна только администратору системы. Обычный пользователь, владелец ресурса и пользователь с предоставленным доступом не могут получать сведения о том, кто загрузил, просматривал, скачивал или изменял файл, а также сведения о пользователях, которые ещё не просматривали файл.

### SCOPE-ACL

Только администратор системы назначает пользователям наборы разрешений в отношении выбранных папок, изменяет назначенные наборы и отзывает доступ. Назначенный набор разрешений наследуется на вложенные элементы и используется для проверки разрешённости операций пользователя над доступными объектами.

### SCOPE-INDEPENDENT-PERMISSIONS

Для любого пользователя, не обладающего глобальными административными полномочиями, разрешённость файловых операций над ресурсом определяется независимо настраиваемым действующим набором разрешений. Факт владения ресурсом, создание или загрузка объекта и наличие одного разрешения сами по себе не предоставляют права на другие операции. Независимо определяются разрешения на просмотр содержимого папки, получение метаданных файла, просмотр содержимого файла, получение исходного файла, создание папок, загрузку новых файлов, изменение содержимого файла, переименование, перемещение и удаление. Допустима любая комбинация этих разрешений, включая пустой набор. Право просмотра содержимого файла не предоставляет право получения исходного файла. Право просмотра содержимого папки не предоставляет право получения метаданных файла, и право получения метаданных файла не предоставляет право просмотра содержимого папки. Право создания папок не предоставляет право загрузки новых файлов, и право загрузки новых файлов не предоставляет право создания папок. Право загрузки нового файла не предоставляет автоматически право изменять, переименовывать, перемещать или удалять этот файл. Право переименования не предоставляет право перемещения, и право перемещения не предоставляет право переименования. Факт владения ресурсом не предоставляет владельцу дополнительных разрешений и не позволяет обходить проверки разрешений. Создание или загрузка объекта пользователем не предоставляет ему автоматически дополнительных разрешений на этот объект. Администратор системы является единственным актором, чьи глобальные административные полномочия позволяют выполнять операции над ресурсами независимо от назначенного набора разрешений.

### SCOPE-HIDDEN-ANCESTORS

Пользователь, которому предоставлен доступ к вложенной папке, видит эту папку и доступное содержимое внутри неё, но не получает доступ и не видит родительскую структуру, если отдельного права на неё у него нет. Это ограничение не распространяется на администратора системы с глобальными административными полномочиями.

### SCOPE-CHANGE-LOG

Формирование единого упорядоченного журнала изменений файлового дерева и прав доступа, пригодного для последующей синхронизации клиентов.

### SCOPE-DELETION-TRACKING

Удаление файла или папки должно фиксироваться как изменение, доступное через протокол синхронизации, чтобы клиент мог корректно отразить удаление в своём локальном состоянии.

### SCOPE-SYNC-PROTOCOL

Сервер предоставляет через API изменения после позиции единого журнала, указанной sync-клиентом. Sync-клиент самостоятельно хранит локально позицию последнего успешно обработанного изменения и передаёт её серверу при последующих запросах. Сервер возвращает изменения после указанной клиентом позиции и не хранит текущую позицию синхронизации конкретного клиента или устройства. Клиент изменяет свою локально хранимую позицию только после успешной обработки полученных изменений.

### SCOPE-VERSIONING

Система хранит текущую версию каждого изменяемого файла или узла. Изменение содержимого, переименование и перемещение существующего объекта выполняются относительно известной вызывающей стороне версии объекта и при успешном выполнении изменяют его текущую версию. Удаление существующего объекта также выполняется относительно известной вызывающей стороне версии и должно отклоняться, если эта версия устарела. Создание новой папки или загрузка нового файла не требуют версии создаваемого объекта, поскольку до операции он не существует.

### SCOPE-CONFLICT

Конфликтующее изменение существующего объекта, основанное на устаревшей версии, отклоняется без автоматического разрешения конфликта сервером.

# Акторы

## ACTOR-ADMIN

**Родительский актор:** ACTOR-USER

Пользователь с глобальными административными полномочиями, который может работать со всеми файлами и папками системы, управлять доступом к ним и выполнять административные операции независимо от их владельца и назначенных прав доступа.

## ACTOR-ANONYMOUS-USER

Неаутентифицированный пользователь, который может аутентифицироваться в системе.

## ACTOR-USER

Аутентифицированный пользователь облачного хранилища, который работает с доступными ему файлами и папками.

## ACTOR-RESOURCE-OWNER

**Родительский актор:** ACTOR-USER

Пользователь в контексте принадлежащих ему файлов и папок; владение определяет принадлежность ресурса, но само по себе не предоставляет разрешений на операции с ним и не позволяет обходить действующий набор разрешений.

## ACTOR-SHARED-USER

**Родительский актор:** ACTOR-USER

Пользователь в контексте файлов и папок другого пользователя, к которым ему предоставлен доступ; его действия ограничены назначенным набором разрешений.

## ACTOR-SYNC-CLIENT

Будущий клиент облачного хранилища, действующий от имени аутентифицированного пользователя и представляющий конкретное клиентское устройство, который использует серверный протокол изменений для синхронизации локального состояния.

# Бизнес-процессы

## BP-ADMIN-CREATE-USER — создание учётной записи администратором

Администратор создаёт новую учётную запись пользователя по переданным данным, если эти данные допустимы и позволяют создать новую учётную запись без конфликта с уже существующей.

**Последовательность:**

1. **Передача данных.** Администратор передаёт данные новой учётной записи.
2. **Проверка данных.** Система проверяет, что переданные данные достаточны и допустимы для создания учётной записи. Если проверка не пройдена, процесс завершается без создания учётной записи.
3. **Проверка существующей учётной записи.** Система проверяет, что данные новой учётной записи не конфликтуют с уже существующей учётной записью. Если конфликт обнаружен, процесс завершается без создания новой учётной записи.
4. **Создание учётной записи.** Если предыдущие проверки успешны, система создаёт новую учётную запись пользователя.

**Успешный результат:** существует новая учётная запись, которую пользователь может использовать для последующей самостоятельной аутентификации.

Создание учётной записи администратором **не создаёт пользовательскую сессию для нового пользователя**.

**Связи:**

* UC-ADMIN-CREATE-USER
* SCOPE-AUTH
* SCOPE-ADMINISTRATION

## BP-AUTH-AUTHENTICATE — аутентификация пользователя

Неаутентифицированный пользователь подтверждает свою принадлежность существующей учётной записи с помощью переданных аутентификационных данных. При успешной проверке система начинает пользовательскую сессию.

**Последовательность:**

1. **Передача данных.** Пользователь передаёт аутентификационные данные.
2. **Проверка данных.** Система проверяет, что переданные данные достаточны и допустимы для попытки аутентификации. Если проверка не пройдена, процесс завершается без создания пользовательской сессии.
3. **Подтверждение учётной записи.** Система проверяет, что переданные данные позволяют подтвердить принадлежность пользователя существующей учётной записи. Если подтвердить аутентификацию не удалось, процесс завершается без создания пользовательской сессии.
4. **Начало сессии.** Если аутентификация подтверждена, система начинает пользовательскую сессию для соответствующей учётной записи.

**Успешный результат:** пользователь аутентифицирован и существует пользовательская сессия, от имени которой он может выполнять доступные ему операции системы.

**Связи:**

* UC-AUTH-AUTHENTICATE
* SCOPE-AUTH

## BP-AUTH-GET-CURRENT-USER — получение текущего пользователя

Аутентифицированный пользователь получает данные учётной записи, которой соответствует его текущая пользовательская сессия.

**Последовательность:**

1. **Запрос данных.** Пользователь запрашивает данные текущей учётной записи в рамках своей пользовательской сессии.
2. **Проверка сессии.** Система проверяет, что пользовательская сессия существует и действительна. Если действительной сессии нет, процесс завершается без выдачи данных учётной записи.
3. **Определение учётной записи.** Система определяет учётную запись пользователя, которой соответствует действующая сессия.
4. **Выдача данных.** Система возвращает данные определённой текущей учётной записи.

**Успешный результат:** пользователь получает данные своей текущей учётной записи, соответствующей действующей пользовательской сессии.

**Связи:**

* UC-AUTH-GET-CURRENT-USER
* SCOPE-AUTH
